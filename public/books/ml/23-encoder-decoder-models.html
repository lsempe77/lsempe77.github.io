Transformer families defined by information flow

Chapter orientation

Why this chapter matters

A Transformer block is a computational unit, not a complete model family. The same block can be arranged so that every input position sees the whole input, so that each output position sees only an earlier prefix, or so that one sequence is encoded before another sequence retrieves from it. These choices define encoder-only, decoder-only, and encoder-decoder models.

The distinction follows from information flow rather than from a brand name. It determines the masks, the available context at each representation, the usual output interface, and the work performed during generation. This chapter uses small tensor examples to compare the three configurations. Tokenisation and detailed language-model objectives are deferred to Chapters 24 and 25.

Learning objectives

By the end of this chapter, you should be able to:

  • distinguish encoder-only, decoder-only, and encoder-decoder Transformer configurations;
  • state the self-attention eligibility rule in each component;
  • explain cross-attention as target queries retrieving from encoded source keys and values;
  • identify the source and target axes in a sequence-to-sequence model;
  • describe which outputs can be computed in parallel and which require autoregressive steps;
  • implement and test a small encoder-decoder information-flow skeleton;
  • match a model family to a stated representation, generation, or conditional-generation requirement; and
  • report the architecture and masking choices needed to reproduce a model result.

Running example

Let a source sequence have four representations, \(X^{src}\in\mathbb{R}^{B\times4\times D}\), and a target prefix have three, \(X^{tgt}\in\mathbb{R}^{B\times3\times D}\). An encoder produces four contextual source representations. A decoder produces three target representations, each constrained to its own earlier target positions but able to retrieve from all valid source positions through cross-attention.

Level 1 - Intuition

Encoders produce context-aware representations

An encoder-only model applies unmasked self-attention to an input sequence. A representation at one position can use content on both its left and right, subject to padding and any task-specific restrictions. The usual result is a contextual representation for every input position, followed by a task-specific head for classification, tagging, retrieval, or another prediction.

This arrangement fits tasks where the full input is available before the output is required. It is not a direct left-to-right generator because its representations can use later input content. BERT is a prominent encoder-only pretraining design built around bidirectional conditioning (Devlin et al. 2019).

Decoders represent prefixes and generate conditionally on them

A decoder-only model applies causal self-attention. Position \(t\) may retrieve from positions at or before \(t\), but not future positions. Its output at each location can therefore be used to parameterise a prediction about the next position without accessing information that would be unavailable during generation.

At training time, representations for a supplied sequence can often be computed in parallel under a triangular mask. At inference time, the next generated item changes the prefix, so decoding proceeds step by step. The mask defines the information boundary; the token-level prediction objective will be derived in Chapter 25.

Encoder-decoder models separate source understanding from target generation

An encoder-decoder model has two sequences with different roles. The encoder reads the full source. The decoder reads an autoregressive target prefix. Cross-attention then lets each target position retrieve from the encoded source. This is useful when the output is a new sequence conditioned on an input sequence, as in translation, summarisation, or structured generation.

The cross-attention matrix is rectangular because target queries and source keys may have different lengths. It is not a second causal mask: source availability is usually controlled by source padding and by the boundary defining the input, while target self-attention preserves the autoregressive restriction.

Level 1 identifies the three information patterns. Level 2 follows the tensors and masks through them.

Level 2 - Mechanics

Encoder-only stacks use one sequence throughout

Starting from input representations \(X\in\mathbb{R}^{B\times S\times D}\), an encoder stack applies blocks whose self-attention keys and values come from the same \(X\)-derived sequence. With valid-token mask \(M\), every valid query can attend to every valid key. The final sequence \(H^{enc}\in\mathbb{R}^{B\times S\times D}\) can support token-level outputs or be pooled into a sequence-level representation under a stated pooling rule.

Pooling is a model decision, not an inevitable property of encoders. Mean pooling, a selected special-position representation, and learned attention pooling produce different output functions and handle padding differently. A report should identify which representation was sent to the prediction head.

Decoder-only stacks preserve a growing prefix

For target representations \(Y\in\mathbb{R}^{B\times T\times D}\), a causal decoder block uses a triangular target self-attention mask. At position \(t\), the block can use target positions \(0,\ldots,t\). During cached inference, earlier projected keys and values can be retained, while the new query uses the correct global positional offset from Chapter 21.

Training and inference use the same causal information rule but different inputs. During teacher-forced training, the observed earlier target items form the prefix at every position, making the full shifted target sequence available for parallel masked computation. During generation, the model’s own selected earlier items form the prefix and each new selection changes the next input. A reported training loss therefore does not by itself measure errors accumulated during a long generated sequence.

Code 
def causal_eligibility(length):
    return np.tril(np.ones((length,length),dtype=bool))
def cross_eligibility(target_length,source_valid):
    return np.broadcast_to(np.asarray(source_valid,dtype=bool),(target_length,len(source_valid)))

print("decoder eligibility at target position 2:",causal_eligibility(4)[2].astype(int))
print("cross-attention with one padded source key:\n",cross_eligibility(3,[True,True,False,True]).astype(int))

The causal mask applies across target positions. The source-valid mask applies across source keys for every target query. Combining them as if source and target were the same axis is a common cross-attention bug.

Encoder-decoder blocks add cross-attention between two sequences

Let \(H^{enc}\in\mathbb{R}^{B\times S\times D}\) be the final encoded source and \(H^{dec}\in\mathbb{R}^{B\times T\times D}\) the current decoder representation. A decoder cross-attention sublayer constructs queries from the decoder and keys and values from the encoder:

\[Q=H^{dec}W_Q,\qquad K=H^{enc}W_K,\qquad V=H^{enc}W_V,\]

\[C=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{D_k}}+M_{src}\right)V.\]

The score tensor has shape \(B\times H\times T\times S\) after head splitting. Its rows correspond to target queries and columns to source keys. Cross-attention is therefore the query-key-value operation from Chapter 19 with source and target axes kept separate.

The source encoding may be reused at each decoder step, but its padding mask must be reused with it. If a request batch packs sources of different length, the cross-attention mask is not optional metadata: it defines which memory locations are data and which are fill values.

Code 
source=np.array([[1.,.2],[.8,.5],[.1,.9],[.4,.3]])
target=np.array([[.6,.1],[.2,.7],[.5,.4]])
scores=target@source.T/np.sqrt(2)
source_valid=np.array([True,True,False,True]); masked=np.where(source_valid[None,:],scores,-np.inf)
weights=np.exp(masked-masked.max(axis=1,keepdims=True)); weights/=weights.sum(axis=1,keepdims=True)
context=weights@source
print("scores, weights, context:",scores.shape,weights.shape,context.shape)
print("padded source mass:",weights[:,2].sum())

The target length is three and source length four, so the score matrix is three by four. Every target query has zero weight on the padded source position after masking. This check belongs alongside output-quality metrics because a wrong source mask can make a model appear to work while using padding artefacts.

Level 2 has separated the model-family data paths. Level 3 states the associated conditional distributions and implements their mask contracts.

Level 3 - Mathematics & Code

Output factorisation follows the information boundary

For a decoder-only sequence \(y_1,\ldots,y_T\), causal conditioning yields the factorisation

\[p(y_{1:T})=\prod_{t=1}^{T}p(y_t\mid y_{<t}).\]

For conditional generation given a source \(x_{1:S}\), an encoder-decoder model uses

\[p(y_{1:T}\mid x_{1:S})=\prod_{t=1}^{T}p(y_t\mid y_{<t},x_{1:S}).\]

The equations state available information, not the vocabulary or loss implementation. A decoder-only model may receive a prompt as part of its prefix; an encoder-decoder model separates the conditioning source and generated target through separate streams and cross-attention.

Code 
import torch
from torch import nn

torch.manual_seed(23)
source=torch.randn(2,4,8); target=torch.randn(2,3,8)
cross=nn.MultiheadAttention(8,2,batch_first=True,dropout=0.0)
source_padding=torch.tensor([[False,False,True,False],[False,False,False,False]])
context,weights=cross(target,source,source,key_padding_mask=source_padding,need_weights=True,average_attn_weights=False)
print("context shape:",tuple(context.shape))
print("weights shape:",tuple(weights.shape))
print("masked source mass:",weights[0,:,:,2].sum().item())

The key_padding_mask is defined on source keys. The target queries remain present; a separate target padding policy is required if the target batch also contains padded queries. Frameworks differ on whether True means ignore or allow, so a hand-checked test is preferable to assuming a convention.

A minimal encoder-decoder skeleton exposes the two masks

Code 
class TinyEncoderDecoder(nn.Module):
    def __init__(self,width=8,heads=2,ff_width=16):
        super().__init__()
        self.encoder=nn.TransformerEncoderLayer(width,heads,ff_width,batch_first=True,dropout=0.0,norm_first=True)
        self.decoder=nn.TransformerDecoderLayer(width,heads,ff_width,batch_first=True,dropout=0.0,norm_first=True)
    def forward(self,source,target,source_padding=None,target_padding=None):
        memory=self.encoder(source,src_key_padding_mask=source_padding)
        t=target.shape[1]; target_causal=torch.triu(torch.ones(t,t,device=target.device,dtype=torch.bool),diagonal=1)
        return self.decoder(target,memory,tgt_mask=target_causal,memory_key_padding_mask=source_padding,tgt_key_padding_mask=target_padding)

model=TinyEncoderDecoder().eval(); source=torch.randn(1,4,8); target=torch.randn(1,3,8)
source_padding=torch.tensor([[False,False,False,True]])
out=model(source,target,source_padding=source_padding)
print("encoder-decoder output:",tuple(out.shape))

The encoder processes source representations once in this minimal forward pass. The decoder’s tgt_mask prevents future target access; memory_key_padding_mask prevents access to padded source positions. The source encoder and target decoder can have different sequence lengths while retaining the same model width for cross-attention.

Perturbation tests distinguish source from future target information

Code 
changed_future=target.clone(); changed_future[:,2]+=100
base=model(source,target,source_padding=source_padding); future_changed=model(source,changed_future,source_padding=source_padding)
changed_source=source.clone(); changed_source[:,0]+=100
source_changed=model(changed_source,target,source_padding=source_padding)
print("earlier target outputs unchanged by future target:",torch.allclose(base[:,:2],future_changed[:,:2],atol=1e-6))
print("target output can change when valid source changes:",not torch.allclose(base,source_changed))

The two tests express different contracts. Causal target self-attention prevents a future target perturbation from affecting earlier output positions. Cross-attention permits a valid source perturbation to affect target representations. A model that passes only one of these tests has not established the complete encoder-decoder information boundary.

The tests use random untrained parameters, so the magnitude or direction of the source effect has no semantic interpretation. Their purpose is architectural: a permitted input path exists, and a prohibited future-target path does not. A trained system requires additional tests for output-head alignment, tokenizer boundaries, and the evaluation data pipeline.

Level 4 - Research & Systems

Architecture choice depends on the output contract

Encoder-only models are appropriate when the output is a representation or a prediction available after reading a complete input. Decoder-only models support left-to-right generation from a prefix. Encoder-decoder models make a source-target distinction explicit and can encode a source once while a target decoder repeatedly retrieves from it. These are general architectural consequences, not exclusive task assignments: a model family can be adapted to tasks beyond its most common examples.

The choice affects serving as well as modelling. An encoder-only retrieval or classification service can batch complete inputs and return outputs after a forward pass. A decoder-only service maintains a growing prefix and usually schedules sequential token steps across active requests. An encoder-decoder service has a source-encoding stage followed by target decoding, with source memory retained for the request. The appropriate design depends on the output contract, expected source and target lengths, latency requirements, and the available supervision.

BERT exemplifies bidirectional encoder representations (Devlin et al. 2019). T5 uses an encoder-decoder text-to-text framework (Raffel et al. 2020), and BART pre-trains a sequence-to-sequence architecture through denoising (Lewis et al. 2020). The examples establish that the families are used in practice; they do not imply that pretraining objective, data, scale, or evaluation can be inferred from the architecture alone.

Source encoding and target decoding have separate costs

An encoder-decoder service must account for source encoding, decoder self-attention over an increasing target prefix, cross-attention from each target query to source memory, and the memory retained for cached keys and values. A long source can make cross-attention costly at every decoding step even when the target is short. A long target increases decoder self-attention and cache size. Latency, memory, and throughput depend on both axes, batch composition, decoding strategy, dtype, and kernel implementation.

Model interfaces should also state ownership of special positions, boundary tokens, padding, attention masks, positional offsets, and output-head alignment. Off-by-one target shifts can produce superficially plausible training losses while teaching a decoder to use the wrong target position. Source and target tokenisation may share a vocabulary or differ; the choice belongs to the model specification and is taken up in Chapter 24.

Evaluation must respect what the model was allowed to see

A bidirectional encoder evaluation can use the complete input if that input would genuinely be available at the time of prediction. A causal decoder evaluation must not include the reference continuation inside the prompt. Conditional generation must ensure that target-side labels do not enter source features or cached decoder state. These are data and evaluation boundaries as much as mask boundaries.

An audit should record architecture family, number and type of blocks, normalisation convention, position method, source and target length distributions, mask semantics, padding and packing policy, vocabulary interface, target shift, generation settings, cache policy, and evaluation-time input availability. It should test source-padding invariance, target causal invariance, source-perturbation sensitivity, and exact agreement between cached and full-prefix decoding on a small reference example.

Common misconceptions

  • An encoder is simply a decoder with the mask removed. Its output contract and typical use differ, even though both use Transformer blocks.
  • Decoder-only training must compute one token at a time. A supplied sequence can be processed in parallel under a causal mask; generation remains sequential.
  • Cross-attention is bidirectional target attention. It uses target queries and source keys and values across distinct axes.
  • The source mask is a triangular target mask. Source padding and target causality constrain different relationships.
  • Encoder-decoder models always have lower inference cost. Their cross-attention adds work at each target step.
  • BERT, T5, and BART names fully specify a model. Variant, objective, data, widths, masks, and checkpoints remain necessary information.
  • Passing a source sequence to a decoder-only prompt is identical to cross-attention. The representation, masking, cache, and source-target boundary differ.
  • A successful generated output proves no future-target leakage occurred. The model and data pipeline require explicit information-boundary tests.

Summary

Encoder-only, decoder-only, and encoder-decoder models arrange Transformer blocks around different information boundaries. Encoders form bidirectional input representations. Decoders preserve a causal target prefix. Encoder-decoder models combine a bidirectional source encoder, a causal target decoder, and target-to-source cross-attention.

The architecture choice affects outputs, masks, inference order, cache design, and valid evaluation inputs. It does not by itself specify a training objective, tokenizer, dataset, or decoding policy.

```{python}
#| label: fig-information-boundaries
#| fig-cap: "The three families use different attention eligibility: encoder self-attention is bidirectional, decoder self-attention is causal, and decoder cross-attention can access valid encoded source positions."
#| fig-alt: "Three small matrices show all cells allowed for an encoder, lower-triangular cells allowed for a decoder, and all cells allowed in a target-query by source-key cross-attention matrix."
fig,axes=plt.subplots(1,3,figsize=(10.5,3.4))
mats=[np.ones((4,4)),np.tril(np.ones((4,4))),np.ones((3,4))]
titles=["encoder self-attention","decoder self-attention","cross-attention"]
for ax,mat,title in zip(axes,mats,titles):
    ax.imshow(mat,cmap="YlGnBu",vmin=0,vmax=1); ax.set_title(title,fontsize=10); ax.set_xlabel("key positions"); ax.set_ylabel("query positions")
    for i in range(mat.shape[0]):
        for j in range(mat.shape[1]): ax.text(j,i,"use" if mat[i,j] else "block",ha="center",va="center",fontsize=7,color="white" if mat[i,j] else "black")
plt.tight_layout(); plt.show()
```

The cross-attention matrix is rectangular because target queries and source keys may have different lengths. It is not a second causal mask: source availability is usually controlled by source padding and by the boundary defining the input, while target self-attention preserves the autoregressive restriction.

Level 1 identifies the three information patterns. Level 2 follows the tensors and masks through them.

## Level 2 - Mechanics

### Encoder-only stacks use one sequence throughout

Starting from input representations $X\in\mathbb{R}^{B\times S\times D}$, an encoder stack applies blocks whose self-attention keys and values come from the same $X$-derived sequence. With valid-token mask $M$, every valid query can attend to every valid key. The final sequence $H^{enc}\in\mathbb{R}^{B\times S\times D}$ can support token-level outputs or be pooled into a sequence-level representation under a stated pooling rule.

Pooling is a model decision, not an inevitable property of encoders. Mean pooling, a selected special-position representation, and learned attention pooling produce different output functions and handle padding differently. A report should identify which representation was sent to the prediction head.

### Decoder-only stacks preserve a growing prefix

For target representations $Y\in\mathbb{R}^{B\times T\times D}$, a causal decoder block uses a triangular target self-attention mask. At position $t$, the block can use target positions $0,\ldots,t$. During cached inference, earlier projected keys and values can be retained, while the new query uses the correct global positional offset from Chapter 21.

Training and inference use the same causal information rule but different inputs. During teacher-forced training, the observed earlier target items form the prefix at every position, making the full shifted target sequence available for parallel masked computation. During generation, the model's own selected earlier items form the prefix and each new selection changes the next input. A reported training loss therefore does not by itself measure errors accumulated during a long generated sequence.

```{python}
def causal_eligibility(length):
    return np.tril(np.ones((length,length),dtype=bool))
def cross_eligibility(target_length,source_valid):
    return np.broadcast_to(np.asarray(source_valid,dtype=bool),(target_length,len(source_valid)))

print("decoder eligibility at target position 2:",causal_eligibility(4)[2].astype(int))
print("cross-attention with one padded source key:\n",cross_eligibility(3,[True,True,False,True]).astype(int))
```

The causal mask applies across target positions. The source-valid mask applies across source keys for every target query. Combining them as if source and target were the same axis is a common cross-attention bug.

### Encoder-decoder blocks add cross-attention between two sequences

Let $H^{enc}\in\mathbb{R}^{B\times S\times D}$ be the final encoded source and $H^{dec}\in\mathbb{R}^{B\times T\times D}$ the current decoder representation. A decoder cross-attention sublayer constructs queries from the decoder and keys and values from the encoder:

$$Q=H^{dec}W_Q,\qquad K=H^{enc}W_K,\qquad V=H^{enc}W_V,$$

$$C=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{D_k}}+M_{src}\right)V.$$

The score tensor has shape $B\times H\times T\times S$ after head splitting. Its rows correspond to target queries and columns to source keys. Cross-attention is therefore the query-key-value operation from Chapter 19 with source and target axes kept separate.


The source encoding may be reused at each decoder step, but its padding mask must be reused with it. If a request batch packs sources of different length, the cross-attention mask is not optional metadata: it defines which memory locations are data and which are fill values.

```{python}
source=np.array([[1.,.2],[.8,.5],[.1,.9],[.4,.3]])
target=np.array([[.6,.1],[.2,.7],[.5,.4]])
scores=target@source.T/np.sqrt(2)
source_valid=np.array([True,True,False,True]); masked=np.where(source_valid[None,:],scores,-np.inf)
weights=np.exp(masked-masked.max(axis=1,keepdims=True)); weights/=weights.sum(axis=1,keepdims=True)
context=weights@source
print("scores, weights, context:",scores.shape,weights.shape,context.shape)
print("padded source mass:",weights[:,2].sum())
```

The target length is three and source length four, so the score matrix is three by four. Every target query has zero weight on the padded source position after masking. This check belongs alongside output-quality metrics because a wrong source mask can make a model appear to work while using padding artefacts.

Level 2 has separated the model-family data paths. Level 3 states the associated conditional distributions and implements their mask contracts.

## Level 3 - Mathematics & Code

### Output factorisation follows the information boundary

For a decoder-only sequence $y_1,\ldots,y_T$, causal conditioning yields the factorisation

$$p(y_{1:T})=\prod_{t=1}^{T}p(y_t\mid y_{<t}).$$

For conditional generation given a source $x_{1:S}$, an encoder-decoder model uses

$$p(y_{1:T}\mid x_{1:S})=\prod_{t=1}^{T}p(y_t\mid y_{<t},x_{1:S}).$$

The equations state available information, not the vocabulary or loss implementation. A decoder-only model may receive a prompt as part of its prefix; an encoder-decoder model separates the conditioning source and generated target through separate streams and cross-attention.

```{python}
import torch
from torch import nn

torch.manual_seed(23)
source=torch.randn(2,4,8); target=torch.randn(2,3,8)
cross=nn.MultiheadAttention(8,2,batch_first=True,dropout=0.0)
source_padding=torch.tensor([[False,False,True,False],[False,False,False,False]])
context,weights=cross(target,source,source,key_padding_mask=source_padding,need_weights=True,average_attn_weights=False)
print("context shape:",tuple(context.shape))
print("weights shape:",tuple(weights.shape))
print("masked source mass:",weights[0,:,:,2].sum().item())
```

The `key_padding_mask` is defined on source keys. The target queries remain present; a separate target padding policy is required if the target batch also contains padded queries. Frameworks differ on whether `True` means ignore or allow, so a hand-checked test is preferable to assuming a convention.

### A minimal encoder-decoder skeleton exposes the two masks

```{python}
class TinyEncoderDecoder(nn.Module):
    def __init__(self,width=8,heads=2,ff_width=16):
        super().__init__()
        self.encoder=nn.TransformerEncoderLayer(width,heads,ff_width,batch_first=True,dropout=0.0,norm_first=True)
        self.decoder=nn.TransformerDecoderLayer(width,heads,ff_width,batch_first=True,dropout=0.0,norm_first=True)
    def forward(self,source,target,source_padding=None,target_padding=None):
        memory=self.encoder(source,src_key_padding_mask=source_padding)
        t=target.shape[1]; target_causal=torch.triu(torch.ones(t,t,device=target.device,dtype=torch.bool),diagonal=1)
        return self.decoder(target,memory,tgt_mask=target_causal,memory_key_padding_mask=source_padding,tgt_key_padding_mask=target_padding)

model=TinyEncoderDecoder().eval(); source=torch.randn(1,4,8); target=torch.randn(1,3,8)
source_padding=torch.tensor([[False,False,False,True]])
out=model(source,target,source_padding=source_padding)
print("encoder-decoder output:",tuple(out.shape))
```

The encoder processes source representations once in this minimal forward pass. The decoder's `tgt_mask` prevents future target access; `memory_key_padding_mask` prevents access to padded source positions. The source encoder and target decoder can have different sequence lengths while retaining the same model width for cross-attention.

### Perturbation tests distinguish source from future target information

```{python}
changed_future=target.clone(); changed_future[:,2]+=100
base=model(source,target,source_padding=source_padding); future_changed=model(source,changed_future,source_padding=source_padding)
changed_source=source.clone(); changed_source[:,0]+=100
source_changed=model(changed_source,target,source_padding=source_padding)
print("earlier target outputs unchanged by future target:",torch.allclose(base[:,:2],future_changed[:,:2],atol=1e-6))
print("target output can change when valid source changes:",not torch.allclose(base,source_changed))
```

The two tests express different contracts. Causal target self-attention prevents a future target perturbation from affecting earlier output positions. Cross-attention permits a valid source perturbation to affect target representations. A model that passes only one of these tests has not established the complete encoder-decoder information boundary.

The tests use random untrained parameters, so the magnitude or direction of the source effect has no semantic interpretation. Their purpose is architectural: a permitted input path exists, and a prohibited future-target path does not. A trained system requires additional tests for output-head alignment, tokenizer boundaries, and the evaluation data pipeline.

## Level 4 - Research & Systems

### Architecture choice depends on the output contract

Encoder-only models are appropriate when the output is a representation or a prediction available after reading a complete input. Decoder-only models support left-to-right generation from a prefix. Encoder-decoder models make a source-target distinction explicit and can encode a source once while a target decoder repeatedly retrieves from it. These are general architectural consequences, not exclusive task assignments: a model family can be adapted to tasks beyond its most common examples.

The choice affects serving as well as modelling. An encoder-only retrieval or classification service can batch complete inputs and return outputs after a forward pass. A decoder-only service maintains a growing prefix and usually schedules sequential token steps across active requests. An encoder-decoder service has a source-encoding stage followed by target decoding, with source memory retained for the request. The appropriate design depends on the output contract, expected source and target lengths, latency requirements, and the available supervision.

BERT exemplifies bidirectional encoder representations [@devlin2019bert]. T5 uses an encoder-decoder text-to-text framework [@raffel2020t5], and BART pre-trains a sequence-to-sequence architecture through denoising [@lewis2020bart]. The examples establish that the families are used in practice; they do not imply that pretraining objective, data, scale, or evaluation can be inferred from the architecture alone.

### Source encoding and target decoding have separate costs

An encoder-decoder service must account for source encoding, decoder self-attention over an increasing target prefix, cross-attention from each target query to source memory, and the memory retained for cached keys and values. A long source can make cross-attention costly at every decoding step even when the target is short. A long target increases decoder self-attention and cache size. Latency, memory, and throughput depend on both axes, batch composition, decoding strategy, dtype, and kernel implementation.

Model interfaces should also state ownership of special positions, boundary tokens, padding, attention masks, positional offsets, and output-head alignment. Off-by-one target shifts can produce superficially plausible training losses while teaching a decoder to use the wrong target position. Source and target tokenisation may share a vocabulary or differ; the choice belongs to the model specification and is taken up in Chapter 24.

### Evaluation must respect what the model was allowed to see

A bidirectional encoder evaluation can use the complete input if that input would genuinely be available at the time of prediction. A causal decoder evaluation must not include the reference continuation inside the prompt. Conditional generation must ensure that target-side labels do not enter source features or cached decoder state. These are data and evaluation boundaries as much as mask boundaries.

An audit should record architecture family, number and type of blocks, normalisation convention, position method, source and target length distributions, mask semantics, padding and packing policy, vocabulary interface, target shift, generation settings, cache policy, and evaluation-time input availability. It should test source-padding invariance, target causal invariance, source-perturbation sensitivity, and exact agreement between cached and full-prefix decoding on a small reference example.

## Common misconceptions

- **An encoder is simply a decoder with the mask removed.** Its output contract and typical use differ, even though both use Transformer blocks.
- **Decoder-only training must compute one token at a time.** A supplied sequence can be processed in parallel under a causal mask; generation remains sequential.
- **Cross-attention is bidirectional target attention.** It uses target queries and source keys and values across distinct axes.
- **The source mask is a triangular target mask.** Source padding and target causality constrain different relationships.
- **Encoder-decoder models always have lower inference cost.** Their cross-attention adds work at each target step.
- **BERT, T5, and BART names fully specify a model.** Variant, objective, data, widths, masks, and checkpoints remain necessary information.
- **Passing a source sequence to a decoder-only prompt is identical to cross-attention.** The representation, masking, cache, and source-target boundary differ.
- **A successful generated output proves no future-target leakage occurred.** The model and data pipeline require explicit information-boundary tests.

## Summary

Encoder-only, decoder-only, and encoder-decoder models arrange Transformer blocks around different information boundaries. Encoders form bidirectional input representations. Decoders preserve a causal target prefix. Encoder-decoder models combine a bidirectional source encoder, a causal target decoder, and target-to-source cross-attention.

The architecture choice affects outputs, masks, inference order, cache design, and valid evaluation inputs. It does not by itself specify a training objective, tokenizer, dataset, or decoding policy.
