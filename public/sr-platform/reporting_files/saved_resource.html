What makes this reconstructable, not just presentable

the report is a read of the data, not a separate document
One data store, one count
The flow diagram's numbers and the checklist's item 16b are both queries against the same decision table — they cannot silently drift apart the way a hand-maintained flow diagram can.
The ledger, not a memory
Model, call count, token spend and override rate come from the same append-only llm_calls ledger every AI call already writes to — the statement is read, not recalled.
Audit log, per decision
A paginated, filterable trail of every decision — by reference, by stage, by actor — sits one click behind the report, for the question a report alone can't answer: "show me exactly how you got there."
Exported, never stored stale
The .docx bundle is rendered on demand from current data. There is no separately-maintained report file that can fall out of sync with a late correction.

This is a static direction for the reporting screens, not wired code. The flow-diagram boxes, the checklist source-pill, and the AI-use statement grid are the new patterns this screen contributes to the shared kit.
