What the version history actually protects

a priori vs. post hoc, decided by the service, not the reviewer's memory
Immutable baseline
v1 is frozen the moment the protocol is registered. Every later edit is a new version, never an overwrite — so "what did we say before we saw any results" is always answerable.
Mandatory amendment reason
Every change after registration requires a written reason and shows a before/after diff. Silent edits to a registered protocol are not possible.
A priori, enforced
An analysis is only "a priori" if its name appears in the v1 baseline. Anything added later is automatically labelled post hoc — a claim the service checks, not one a reviewer has to remember to make honestly.
One set of eligibility criteria
The E1/E2/E3 codes defined here are the exact objects a full-text screening exclusion must cite, and the exact objects the PRISMA report counts against. Write them once.

This is a static direction for the protocol screen, not wired code. It shares the same tokens, type scale and component vocabulary as the rest of the design language — the framework-switcher tabs, the AI-drafted narrative panel, and the version-history spine are the three pieces this screen contributes to the shared kit.
